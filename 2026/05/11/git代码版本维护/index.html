git代码版本维护

初始状态：本地无任何代码、无Git仓库、远程有包含v3主分支的仓库

目标：在 IDEA 中完成“拉取v3代码→创建个人分支→开发修改→推送分支→同步v1最新代码”的完整操作步骤。

1 前置：克隆远程仓库到本地

  1. 先把远程仓库(含v3主分支)完整拉到本地电脑

    打开 IDEA，点击顶部菜单栏 File → New → Project from Version Control；

  2. 在弹出的窗口中：

    Version control 选择 Git；

    URL 输入远程仓库的 Git 地址(比如https://github.com/xxx/xxx.git 或 git@github.com:xxx/xxx.git)；

    Directory 选择本地要存放代码的文件夹(比如D:\code\project)；

    点击 Clone 按钮，IDEA 会自动拉取远程仓库的所有分支(包括v3)到本地；

  3. 等待底部控制台提示 “Clone completed successfully”，克隆完成后 IDEA 会自动打开项目。

2 基于v3创建并切换到个人分支

开发者A(v3_1分支)操作：

  1. 确认当前分支：

    IDEA 右下角会显示当前分支(默认是v3，因为远程主分支是v3)，若不是v3，点击右下角分支名 → 选择v3 → 点击Checkout(检出)，确保基于最新 v3 创建分支；

  2. 创建个人分支：

    方式 1：点击右下角分支名 → 点击New Branch；

    方式 2：顶部菜单栏 Git → Branch → New Branch；

  3. 在弹出的 “Create New Branch” 窗口中：

    Name 输入分支名 v3_1；

    勾选 Checkout branch(创建后直接切换到该分支)；

    确认 Based on 是 origin/v3(基于远程v3分支)；

  4. 点击 Create 按钮，此时 IDEA 右下角分支名会变成v3_1，表示已成功创建并切换到个人分支。

开发者B(v3_2 分支)操作和 A 完全一致，仅将分支名改为v3_2即可。

3 本地开发并提交代码

在 v3_1/v3_2 分支下修改代码(比如修改某个文件、新增功能)

  1. 提交本地修改：

    方式 1：点击 IDEA 左侧边栏 Commit 按钮(像对勾的图标)；

    方式 2：顶部菜单栏 Git → Commit；

  2. 在弹出的 “Commit Changes” 窗口中：

    勾选要提交的文件(默认全选，可取消不需要的)；

    在Commit message框中填写清晰的提交说明(比如[v3_1] 修复用户列表展示bug)；

    点击 Commit 按钮(若提示 “Commit and Push”，先只点Commit，后续单独推送)；

  3. 提交完成后，代码仅保存在本地 v3_1/v3_2 分支，还未推送到远程。

4 第一次推送个人分支到远程

因为 v3_1/v3_2 是本地新建的分支，远程仓库还没有这个分支，第一次推送需要关联远程分支。

  1. 点击顶部菜单栏 Git → Push(或工具栏的 “推送” 图标)；
  2. 在弹出的 “Push Commits” 窗口中，IDEA 会提示：The current branch ‘v3_1’ has no upstream branch. Do you want to set ‘origin/v3_1’ as its upstream branch?(当前分支无上游，是否设置 origin/v3_1 为上游)；
  3. 点击 Set upstream and push 按钮；
  4. 等待控制台提示 “Push successful”，此时远程仓库会新增 v3_1/v3_2 分支，且本地分支与远程分支关联成功。

5 同步远程 v3 的最新代码到个人分支

如果开发过程中，远程v3有新代码(比如其他人提交)，需要同步到自己的分支

  1. 确保当前分支是 v3_1/v3_2(右下角确认)；
  2. 拉取远程 v3 最新代码：点击顶部菜单栏 Git → Fetch；
  3. 合并远程 v3 到个人分支：点击顶部菜单栏 Git → Merge，在弹窗中选择origin/v3，点击Merge；
  4. 处理冲突(若有)：冲突文件会标红，打开文件后删除<<<<<<< HEAD/=======/>>>>>>> origin/v3分隔符，保留正确代码，然后点击Commit提交冲突解决结果；
  5. 推送合并后的代码：再次点击Git → Push，推送更新后的 v3_1/v3_2 到远程。

6 后续开发与推送

之后每次修改代码后，只需重复 “本地提交 → Push” 即可(无需再设置上游，因为第一次推送已关联)：

  1. 修改代码 → 提交(Commit)；
  2. 点击Push，直接推送至远程 v3_1/v3_2 分支。

7 将个人分支合并回v3

当功能开发完成后，需将 v3_1/v3_2 合并到主分支 v3

  1. 切换到 v3 分支：右下角点击分支名 → 选择v3 → Checkout；
  2. 拉取 v3 最新代码：Git → Pull(Pull = Fetch + Merge，直接拉取并合并远程 v3)；
  3. 合并个人分支：Git → Merge → 选择v3_1(或 v3_2) → Merge；
  4. 解决冲突(若有)→ 提交 → 推送 v3 到远程：Git → Push。

附 版本分支维护与切换

有两个大版本需要分别维护，如v3->v3个人分支，v4->v4个人分支，如何在idea中切换维护

  1. 前置：克隆远程仓库（已包含 v3、v4 主分支）

    IDEA：File → New → Project from Version Control

    Version control 选 Git，填入仓库 URL，选本地目录

    点击 Clone，拉取所有远程分支（含 origin/v3、origin/v4）

  2. 检出 v3、v4 两个主分支到本地

    点击 IDEA 右下角分支名 → 展开 Remote Branches

    找到 origin/v3 → Checkout（生成本地 v3 分支）

    找到 origin/v4 → Checkout（生成本地 v4 分支）

  3. 分别创建个人分支

    基于 v3 创建个人分支：

    切到 v3 → 右下角分支 → New Branch → 命名 v3_xxx → 勾选 Checkout

    基于 v4 创建个人分支：

    切到 v4 → 右下角分支 → New Branch → 命名 v4_xxx → 勾选 Checkout

    完成后本地分支：v3、v3_xxx；v4、v4_xxx

  4. 切换维护

    点右下角分支名切换：

    维护 v3_xxx：check out v3_xxx，工作区自动变为 v3 版本代码

    维护 v4_xxx：check outv4_xxx，工作区自动变为 v4 版本代码

    切换后，v3_xxx 的已提交代码只在该分支，v4_xxx 完全看不到，互不干扰。

  5. 各自同步对应主分支最新代码

    同步 v3 → v3_xxx：切到 v3_xxx → Git → Fetch → Merge → 选 origin/v3 → 解决冲突 → Push

    同步 v4 → v4_xxx：切到 v4_xxx → Git → Fetch → Merge → 选 origin/v4 → 解决冲突 → Push

  6. 后续提交 / 推送 / 合并回主分支

    提交推送：修改代码 → Commit → Push（推到对应个人分支）

    合并主分支：

    1. 切到 v3 → Pull → Merge v3_xxx → Push
    2. 切到 v4 → Pull → Merge v4_xxx → Push

  7. v3个人分支修改了代码，v4 checkout时警告提示

    your local changes to the following files would be overwritten by checkout

    v3个人分支 修改了代码，且未提交 / 暂存，v4 分支里刚好也有这些被修改的文件，且内容不一样。Git为防止切换分支后，直接覆盖掉你 v3 分支未保存的修改，会主动阻止切换。

    • 方案 1：【推荐】提交 v3 的修改

      适合：想保留 v3 分支的修改

      1. 打开 IDEA 左侧 Commit 面板（或点底部 Git → Commit）
      2. 勾选你修改的文件
      3. 写提交信息（比如：v3 分支修改 xx 功能）
      4. 点击 Commit（仅提交到本地，不推送）
      5. 再去右下角切换 v4 分支

    • 方案 2：暂存修改

      适合：v3 修改没写完，不想提交，但要临时切 v4

      1. 顶部菜单栏 → Git → Stash Changes
      2. 备注（如：v3 临时修改）→ 点击 Create
      3. 此时工作区清空，再切换 v4 分支

      切回 v3 分支后，恢复暂存：Git → Unstash Changes → 选中刚才的暂存 → Apply（应用）即可。

    • 方案 3：丢弃修改

      适合：v3 的修改是误改 / 无用代码，直接丢掉

      1. 打开 IDEA 左侧 Commit 面板
      2. 右键勾选的修改文件 → Rollback（回滚）
      3. 确认丢弃 → 再切换 v4 分支
